# 功能规范: st CLI 改造为 SKILL 并封装为 Plugin

**功能分支**: `002-skill-plugin-wrap`
**创建时间**: 2026-07-09
**状态**: 草稿
**输入**: 用户描述: "将本项目改造成SKILL并最终封装成Plugin，拆分为st-diagnose诊断、st-analyze分析并给出优化建议、st-optimize应用优化三个SKILL。SKILL中仍然调用st命令，st输出结果或文件，SKILL基于st输出结果进一步操作。"

## 用户场景与测试 _(必填)_

### 用户故事 1 - Token 诊断 (优先级: P1)

用户想要了解当前 CodeBuddy 环境的 Token 占用情况��用户在对话中说"诊断我的 token 占用"或类似表述，AI 自动触发 st-diagnose SKILL，该 SKILL 调用 `st diagnose` 获取诊断报告，然后向用户呈现结构化的诊断结果，包括 MCP/Skill/Plugin/规则/CODEBUDDY.md 的 Token 占用分布和潜在问题。

**优先级原因**: 诊断是所有后续操作的前提，没有诊断数据就无法给出优化建议。这是 MVP 的最小可交付单元。

**独立测试**: 用户在任何 CodeBuddy 会话中表达"诊断 token"意图，系统应自动执行诊断并返回格式化报告。无需安装其他 SKILL 即可独立完成。

**验收场景**:

1. **给定** 用户在一个安装了 save-token Plugin 的 CodeBuddy 会话中，**当** 用户说"帮我诊断一下 token 占用"，**那么** AI 自动调用 st-diagnose SKILL，执行 `st diagnose` 命令，并向用户展示诊断报告（包含 Token 分布、Top 消耗项、数据来源标记）。
2. **给定** `st` 命令未安装，**当** AI 触发 st-diagnose SKILL，**那么** SKILL 检测到命令缺失后，向用户报告"请先安装 st 命令行工具"，并给出安装指引。
3. **给定** `st diagnose` 执行失败（如 headless 探针不可用），**当** SKILL 收到错误输出，**那么** SKILL 向用户展示降级后的诊断结果，并说明哪些数据来源不可用及原因。

---

### 用户故事 2 - 优化分析与建议 (优先级: P2)

用户想要基于诊断结果和使用场景获得针对���的优化建议。AI 触发 st-analyze SKILL，该 SKILL 收集用户的使用场景（日常编码 / 代码审查 / 架构设计 / 全栈开发等）、当前项目类型和技术栈，结合 `st diagnose` 的诊断数据，生成个性化的优化建议列表，按节省量排序。

**优先级原因**: 分析是诊断到执行的桥梁。不同使用场景对工具的需求不同——例如全栈开发者可能需要更多 MCP 工具而纯前端开发者可能只需少量。场景感知使建议更精准。依赖 P1 的诊断能力。

**独立测试**: 用户可在诊断后说"分析我的 token 优化空间"，系统收集场景信息后返回排序后的建议列表。即使不执行，用户也能看到完整的优化方案。

**验收场景**:

1. **给定** 用户已完成诊断（诊断报告可用），**当** 用户说"分析优化空间"，**那么** AI 触发 st-analyze SKILL，收集用户的使用场景和项目情况，结合诊断数据生成个性化优化建议列表，按预计 Token 节省量从高到低排序展示。
2. **给定** 用户未先做诊断，**当** 用户说"分析 token 优化"，**那么** SKILL 自动先执行 `st diagnose` 获取诊断数据，再收集场景信息，最后生成优化建议。
3. **给定** 用户是后端开发者且诊断显示未安装 RTK、MCP 数量 > 5，**当** SKILL 分析，**那么** 建议列表优先推荐"安装 RTK（预计节省 40-60%）"，��对 MCP 工具按使用频率排序建议禁用低频工具。
4. **给定** 诊断结果显示无需优化（Token 占用已在合理范围内），**当** SKILL 分析，**那么** SKILL 返回"当前 Token 占用合理，无需优化"的结论，并说明当前配置已适合该使用场景。
5. **给定** 用户未说明使用场景，**当** SKILL 分析，**那么** SKILL 主动询问用户的主要使用场景（编码/审查/架构等），等待用户回答后再生成建议。

---

### 用户故事 3 - 优化执行 (优先级: P3)

用户在查看优化建议后，想要一键应用这些建议。AI 触发 st-optimize SKILL，该 SKILL 基于分析结果执行实际操作：安装省 Token 工具、修改 CodeBuddy 配置文件。执行前展示将要变更的内容，执行后报告变更结果和总节省量。

**优先级原因**: 执行是完整流程的终点。依赖 P2 的分析结果。部分用户可能只想看建议而不自动执行，因此优先级低于诊断和分析。

**独立测试**: 用户可在查看分析结果后说"应用这些优化"，系统执行 `st optimize --apply` 并报告变更结果。

**验收场景**:

1. **给定** 用户已查看分析结果且同意执行，**当** 用户说"应用这些优化"或"执行优化"，**那么** AI 触发 st-optimize SKILL，执行 `st optimize --apply`，完成后报告每个变更项的状态（成功/失败）和总 Token 节省量。
2. **给定** 优化建议中包含安装工具（如 RTK），**当** SKILL 执行优化，**那么** SKILL 执行工具安装命令并在完成后验证安装结果。
3. **给定** 优化建议中包含配置文件修改（如禁用 MCP），**当** SKILL 执行优化，**那么** SKILL 在执行前自动备份原配置文件，修改后报告备份位置。
4. **给定** 用户尚未做分析和诊断，**当** 用户说"优化我的 token"，**那么** SKILL 先自动执行诊断和分析，展示分析摘要并询问用户确认后再执行。

---

### 用户故事 4 - Plugin 封装与安装 (优先级: P4)

用户想要通过 Plugin 市场安装 save-token 插件，以便在任何项目中使用。Plugin 包含上述三个 SKILL，遵循 CodeBuddy Plugin 标准结构。用户通过 `/plugin install` 安装后，即可在任意会话中自动使用诊断和优化能力。

**优先级原因**: Plugin 封装使得功能可在任意项目中复用，是分发和共享的关键。但核心功能（三个 SKILL）不依赖 Plugin 封装即可工作——Plugin 是打包和分发方式。

**独立测试**: 用户在任意项目中执行 `/plugin install save-token`（或本地路径），安装后在新会话中说"诊断我的 token 占用"，系统应正确触发 st-diagnose SKILL。

**验收场景**:

1. **给定** save-token Plugin 已发布到市场或提供本地路径，**当** 用户执行安装操作，**那么** 三个 SKILL（st-diagnose、st-analyze、st-optimize）注册为命名空间化命令（如 `/save-token:diagnose`）。
2. **给定** Plugin 已安装，**当** 用户在任意项目的新会话中说"帮我诊断 token"，**那么** AI 自动识别并调用 st-diagnose SKILL，无需用户手动输入斜杠命令。
3. **给定** Plugin 包含 `st` 命令依赖声明，**当** 用户安装 Plugin 但未安装 `st` 命令，**那么** Plugin 在首次使��时提示用户安装 `st` CLI 工具。

---

### 边界情况

- 当 `st` CLI 工具未安装时，SKILL 如何处理？（检测命令是否存在，不存在则给出安装指引）
- 当 `st diagnose` 输出格式异常时，SKILL 如何处理？（捕获异常，向用户展示原始输出并说明解析失败）
- 当用户在一个会话中多次触发诊断时，是否复用之前的诊断结果？（默认复用 5 分钟内的诊断结果，用户可通过"重新诊断"触发新诊断）
- 当优化执行过程中部分操作失败时，SKILL 如何处理？（报告每个操作的执行状态，成功的保留，失败的给出原因和建议）
- Plugin 安装后，三个 SKILL 如何与已有的 SKILL（fix-bug、new-feature、ut-writer）共存？（命名空间隔离，不冲突）
- 当 st-analyze 无法确定用户的使用场景时，如何处理？（主动询问，不猜测；用户可选择跳过场景收集，使用通用分析）

## 需求 _(必填)_

### 功能需求

- **FR-001**: 系统必须提供 `st-diagnose` SKILL，当用户表达"诊断 token 占用"意图时，AI 自动触发该 SKILL。
- **FR-002**: `st-diagnose` SKILL 必须调用 `st diagnose` 命令获取诊断数据，并将输出格式化为用户可读的报告。仅做数据收集和呈现，不涉及分析和建议。
- **FR-003**: 系统必须提供 `st-analyze` SKILL，当用户表达"分析优化空间"或"优化建议"意图时，AI 自动触发该 SKILL。
- **FR-004**: `st-analyze` SKILL 必须收集用户的使用场景（日常编码/代码审查/架构设计/全栈开发等）、当前项目类型和技术栈���息。
- **FR-005**: `st-analyze` SKILL 必须先获取诊断数据（如果尚未诊断），结合场景信息生成个性化的优化建议列表。
- **FR-006**: 当用户未提供使用场景信息时，`st-analyze` SKILL 必须主动询问用户的主要使用场景，而非使用默认值。
- **FR-007**: 系统必须提供 `st-optimize` SKILL，当用户表达"执行优化"意图时，AI 自动触发该 SKILL。
- **FR-008**: `st-optimize` SKILL 必须在执行变更前向用户展示将要变更的内容，并获得用户确认。
- **FR-009**: 三个 SKILL 必须能独立运行，不要求用户按固定顺序手动触发。
- **FR-010**: 系统必须将所有三个 SKILL 封装为一个符合 CodeBuddy Plugin 标准的插件。
- **FR-011**: Plugin 必须声明对 `st` CLI 工具的依赖。
- **FR-012**: 当 `st` 命令不可用时，SKILL 必须向用户提供安装指引。
- **FR-013**: `st-optimize` SKILL 必须在修改配置文件前自动备份原文件，并报告备份位置。
- **FR-014**: 三个 SKILL 必须支持 AI 自动触发（通过 description 字段匹配任务）和用户手动调用（通过 `/plugin-name:skill-name` 命令）两种方式。

### 关键实体

- **SKILL 定义**: 每个 SKILL 是一个包含 SKILL.md 文件的目录，定义 SKILL 的名称、描述、工作流程和可使用的工具。三个 SKILL 共享同一个 CLI 后端（`st` 命令），通过不同的子命令实现不同功能。
- **诊断报告**: `st diagnose` 输出的结构化数据，包含 MCP/Skill/Plugin/规则/CODEBUDDY.md 的 Token 占用分布、数据来源标记、采集时间戳。st-diagnose SKILL 将其格式化为用户可读的报告。
- **使用场景**: st-analyze SKILL 收集的用户上下文，包括主要使用场景（编码/审查/架构/全栈）、项目类���（前端/后端/全栈/工具库等）、技术栈，用于生成个性化优化建议。
- **分析结果**: 基于诊断报告和场景信息生成的优化建议列表，每条建议包含操作类型（安装工具/��置修改）、操作内容、预计 Token 节省量、风险等级、与场景的关联说明。
- **Plugin 包**: 符合 CodeBuddy Plugin 标准的目录结构，包含 `.codebuddy-plugin/plugin.json` 清单文件和 `skills/` 目录。

## 成功标准 _(必填)_

### 可衡量的结果

- **SC-001**: 用户在对话中表达"诊断 token"意图后，30 秒内获得诊断报告。
- **SC-002**: 用户在对话中表达"��析优化"意图后，60 秒内获得结合场景的个性化优化建议列表。
- **SC-003**: 用户通过 Plugin 安装后，在任意项目中均可使用诊断和优化能力，无需重复配置。
- **SC-004**: 优化执行过程可回滚——执行前自动备份，用户可在优化后恢复到优化前状态。
- **SC-005**: 三个 SKILL 的 description 描述准确，AI 在用户表达相关意图时能正确自动触发（误触发率低）。

## 假设

1. `st` CLI 工具保持现有的 `diagnose`、`analyze`、`optimize` 子命令，输出格式保持 JSON/结构化文本，SKILL 层只做解析和呈现。
2. 用户已安装 Node.js 环境，因为 `st` 基于 Node.js 运行。
3. Plugin 通过 `skills/` 目录下的 SKILL.md 实现，不需要额外的 `commands/` 或 `agents/`。
4. SKILL 的 context 模式使用默认的 inline 注入（非 fork），因为需要访问对话历史和 `st` 命令输出。
5. Plugin 的命名空间使用 `save-token`（与项目名称一致）。
6. 三个 SKILL 之间通过共享诊断结果文件进行数据传递（而非通过上下文变量传递）。
7. Plugin 通过本地路径 `--plugin-dir` 或市场分发，市场分发方式不在本规范范围内。
8. `st-analyze` 中的使用场景收集通过 AI 对话自然完成（SKILL 引导 AI 向用户提问），不需要额外的 CLI 子命令。
